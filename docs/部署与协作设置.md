# 协作与部署设置

仓库：vew201/yifang-modus-board，必须保持 Private。邀请 XinboChen-Jason 为协作者，授予 Write；邀请发出后仍需对方接受。

## 已提供的流程与首次启用

- CI 工作流随源码上传后在 GitHub 上运行。审查必须查看对应 SHA 的实际结果，不能沿用本机旧报告。
- AI 审核由已连接此仓库的 Codex 执行；原生自动审核在 Codex code-review settings 单独启用。未验证之前不声称已经开启无人值守审核。
- PR 合并门禁只接受白名单审核者对当前 head 的正式 APPROVED，且审核者不能是作者；检查同一 head 和当前 main 基线的 CI。由 /modus merge 请求，控制器只执行 main 上的受信任脚本，不执行 PR 代码。
- 私有仓库的分支保护及 GitHub 原生 auto-merge 取决于账号套餐。无法启用时应明确报告，不能声称 main 已禁止直接推送；合并脚本与部署检查仍保持拒绝未经审核的变更。
- 本机部署需要一次注册仓库专属 Windows runner。只让已审核 main 的部署任务使用带 modus-production 标签的 runner；PR 测试在 GitHub 托管环境运行，不使用正式电脑。
- 首次部署接入完成前，main 合并不表示生产已经更新。首次应用及重启目前受自动审批阻挡，需要使用者启动准备好的部署入口。

## 账号与数据

GitHub 插件目前不提供建仓、协作者管理和 runner 注册接口；这些管理动作需要网页或一次 GitHub CLI 管理授权。不要把密码、个人访问 Token、runner 注册 Token、看板私有接入包放到聊天或 Git。

部署只复制清单内的应用源码；data、正式账号、客户附件、连接和发现密钥不参与 Git 同步。保留数据库备份及上一份代码，启动失败回退代码，避免用旧数据库覆盖可能产生的新写入。独立备份不由回收站清理。

## 提交与审核

合伙人分支如 feature/project-timeline，目标 main。提交 PR 后可把链接发给维护 Codex，要求按 AGENTS.md 审核、运行检查，符合条件后批准并合并。当前 head 改动后旧批准失效。测试失败或迁移、共享文件清理、账号绑定等存在问题时先修复，不通过评论文字绕过门禁。
