# 易方 MODUS 看板录入与维护

本文件属于工作台发布的当前业务规则。专用会话每条用户消息处理前必须检查接入版本：收到可确认属于本轮的 UserPromptSubmit 检查回执时复用；没有本轮回执时，AI先运行稳定入口 launcher.py check。不得把Hook已信任、旧回执或人工模拟Hook测试当作本轮已自动检查。没有变化不下载正文，不设置定时任务。当前运行方式未调用本地Hook时，继续按工作目录AGENTS.md逐消息调用check，不要求人类反复授权或重启。有更新或会话首次使用时，通过rules获取并读取本文件及所需说明，再执行 launcher.py ack --session 当前CODEX_THREAD_ID --release 当前完整release，确认当前会话已读取该版本，然后处理用户任务。写入遇到版本过期或规则未加载时，先同步并重新核对用户原意，不重复执行旧提交。

安装后的稳定入口是技能目录 scripts/modus.py，或 .modus-board.json 记录的客户端目录 launcher.py。业务规则位于该客户端 releases/当前版本 下；凭证独立保存在客户端 connection.json，不属于更新内容。


先阅读 [专用对话说明](references/看板专用对话说明.txt)，据此判断对象和逐项补问信息。需要调用后端时阅读 [接口与脚本](references/接口与脚本.txt)。

用户说要放到看板、记录合作意向、增加或修改任务、归档文件时使用本技能。继承当前会话中已经明确的信息与授权。每次只追问一个阻碍正确录入的关键问题，完整输入可直接整理并提交。

通过 `python scripts/modus.py status` 核对当前连接账号，通过 `state` 查询真实记录和人员编号。根据用户说明确定负责人。明确未知的日期使用空字符串，已确认事项、待确认问题和 AI 建议分别记录。用户要求先登记时，可用明确标记的暂定名称保存意向。

示例中的 scripts/modus.py 指安装后的稳定技能入口；优先使用 .modus-board.json 所记客户端目录的 launcher.py 加相同命令。当前 releases 版本目录中的 scripts/modus.py 是内部实现，不直接执行，以保证先检查版本和会话已读状态。

归档时先准备 JSON 提交文件，再运行 `python scripts/modus.py submit <提交文件>`。修改已有记录时携带读取到的 revision。网络重试沿用同一 request_id，收到 409 时重新读取并核对冲突。以接口成功结果为依据报告提交位置及未决问题。

上传原文件使用 file_path 参数，原文与摘要通过 conversations 记录关联到对应项目、意向或任务。分类区域及文件移动依据用户的实际描述。删除操作使用回收站，关联项目或意向的删除范围需要在用户指令中明确。

所有项目固定为项目准备、资料接收、需求澄清、方案与开工对齐、开发实现、整体验证、交付验收、复盘改进八个阶段。新增内容按用途归入对应阶段，阶段名称和数量不可变更。待办的 stage_id 可选，只作分类；完成、撤回、新增或回收待办都不会改变阶段或项目完成状态。只有用户明确确认实际成果完成时才更新阶段状态，保存完成说明及真实时间。项目开发完成另用 development_done 明确记录；成功仍要求开发全部完成且尾款到账。项目外待办同时留空 project_id、opportunity_id，通过第七页管理并同步首页与归档。

连接配置保存在技能目录的 connection.json 或 MODUS_CONFIG 指定文件。共享技能包时排除该文件。合伙人使用自己的看板账号建立连接。

意向按线索发现、沟通、最终方案报价已提交三阶段维护。依专用对话说明填写结构化来源和沟通字段，上传意向资料到 /api/opportunity_files。沟通阶段默认实际结束后24小时，最终方案提交及其后续跟进默认48小时，新约定优先，不另建重复自动跟进。成功项目必须开发全部完成且尾款到账；启动开发通过 convert 关联项目，失败通过 fail 必填原因。实际发生时间未知时不以录入时间替代。

意向卡片按 last_activity_at 计时，未改动满72小时变灰、满144小时变黑；真实编辑、沟通、文件和跟进行动更新后恢复白色。后端自动维护时间，查询和刷新不重置，不要为改变卡片颜色而伪造业务改动。

回收站默认保留30天，到期由后端自动清理。旧记录缺少删除时间时，从升级时刻起保留完整30天。移入回收站和永久删除是不同操作；人工彻底删除或清空前必须先通过/api/trash/preview取得当前范围和preview_token，向用户展示关联任务、阶段、沟通及附件的实际删除范围，并得到对本次范围的明确确认，再单独调用/api/trash/purge；没有明确永久删除授权时只能移入回收站。禁止把永久删除夹在agent/submit批次中。正常独立项目、意向及其成功失败或工作归档不纳入清理；被永久删除的父记录所拥有的子内容会一起删除，仍属于其他正常记录的共享沟通或附件会保留。
